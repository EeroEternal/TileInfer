# 目标与验收

> 这份文档只回答两件事：**怎么算做到了**、**什么情况必须停下来收缩**。
> 架构见 [`architecture.md`](architecture.md)，数字见 [`performance.md`](performance.md)。

---

## 1. 三条价值（可测量）

| 价值 | 怎么量 | 不许用什么来代替 |
|---|---|---|
| **能部署的模型数** | 状态为"在役"的模型清单，每个模型都有独立证据 | 不许用"支持某家族"这种模糊说法 |
| **相对基线的速度比** | 同机、同参数、同模型的 A/B 比值 | 不许用不同场景的绝对值对比 |
| **每模型边际成本** | 从写声明到在役的实际人日，以及缺口条数 | 不许用"很快就能上" |

---

## 2. "支持一个模型"是四条独立结论

这是本项目最重要的一条口径。四条**分别判定、分别留证**，不允许合成一个"支持"。

| # | 结论 | 怎么判定 | 失败长什么样 |
|---|---|---|---|
| **C1 能跑** | 端到端起服务，正常返回 | 一条固定请求能得到完整输出 | 启动崩 / 首 token 即错 |
| **C2 跑对** | 数值与基线一致 | 同一请求、温度 0，逐位比较对数（4 位小数口径） | 输出通顺但差一点点——最危险的一类 |
| **C3 能上图** | 图捕获真的发生 | 捕获次数 > 0 且回退次数 = 0 | 能跑但每步慢，因为退回逐算子执行 |
| **C4 跑得快** | 相对基线在门槛内 | TPOT ≤ 1.10×、首字 ≤ 1.10×、吞吐 ≥ 0.95× | 数字达标但口径不一致（最常见） |

一条经验：**C2 和 C3 是最容易被跳过、也是事后最贵的两条。**

## 3. 测量矩阵（三类问题必须分开）

混在一起会互相污染：排队会把"一步多快"掩盖成吞吐问题，长输入会把预填充混进单步耗时。

| 组 | 场景 | 看什么 |
|---|---|---|
| **S 达标组** | 单并发短输入 / 单并发 4K / 多并发短输入 / 多并发 2K | 单步地板、首字固定开销、吞吐、排队 |
| **R 风险组** | 单并发 8K / 多并发 8K / 高并发 2K | 长上下文、分页碎片、调度是否线性 |
| **D 诊断组** | 纯解码（输入 1 token）/ 只测预填充 | 排除干扰后的单步成本 / 首字随长度的斜率 |

每场景必须记录：并发数、输入输出长度、`max-num-seqs`、`max-model-len`、显存起始占用、
是否冷启动、是否发生回退。**两臂条件不一致时，这一组数字直接作废。**

三条硬规矩：

1. `max-num-seqs` 必须等于该场景的客户端并发，绝不能小于。
2. 跑数字前先确认两边都"就绪"且窗口内零回退、非冷启动。
3. 同一轮对比内，模型/环境/参数完全一致；改一个参数就重开一轮。

## 4. KPI

| 指标 | 目标 | 备注 |
|---|---|---|
| 在役模型数 | 逐季增加 | 每个都要有四条证据 |
| 相对基线速度比 | 在门槛内（见 C4） | 落后就回退到厂商实现，而不是硬扛 |
| 每模型边际成本 | 不上升 | 用缺口条数与实际人日记录 |
| 接入点数量 | ≤ 8（现为 6） | 涨了就说明接错了 |
| 静默回退次数 | 稳态为 0 | 非 0 视为缺陷，不是"正常降级" |

**明确不用作 KPI 的**：补丁数量、代码行数、自研算子占比。
自研比例高而整体慢，是这个项目最该避免的结果。

---

## 5. 红线（触发就收缩，不再讨论）

| 触发条件 | 动作 |
|---|---|
| 上游每个小版本要改 ≥3 个接入点 | 收缩到"模型实现 + 2–3 个高价值算子"，砍掉通用层 |
| 某类契约只有一个提供者且从未被替换 | 判定为抽象税，合并回模型层 |
| 稳态回退无法压到 0 | 停止加模型，先把回退根因修掉 |
| 接入点引入了可测量的每步开销 | 判定为分支进热路径，回退该接入点 |
| 某模型适配的人日超过"照上游办法硬改"的 3 倍 | 放弃通用路径，退化为专用分支并记录 |

## 6. 证据纪律

- 每个数字必须能追到一次**可复现的运行**（命令、环境、时间戳）。
- 只在一个窗口测过的数字标 **[待复核]**，不能当结论引用。
- 被推翻的结论**保留在案**并标 **[已作废]**，防止重犯。
- 状态文档是唯一权威；README、方案、会议记录里的数字一律不引用。
