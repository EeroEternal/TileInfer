# Qwen3.6 TP=4 / TP=8 运行验证（2026-11-18）

> 控制模型、厂商路径。目的：把"多卡"从 TP=2 扩到 TP=4/8，并确认 TileInfer 这层不干扰
> 厂商分片。**不是** C2 声明：跨 TP 的 C2 按 [`acceptance.md`](../acceptance.md) §2.1.1，
> Qwen3.6 没有 `tolerance_tp`，所以不声明。

## 0. 配置

| 项 | TP=4 | TP=8 |

| 卡 | 物理 0,1,2,3 | 物理 0-7 |

| 参数 | `max-model-len 4096`、`max-num-seqs 4`、`gpu-memory-utilization 0.9`、`--skip-mm-profiling` | 同左 |
| 环境 | CANN 9.3 + triton-ascend + 本仓库代码 | 同左 |
| HCCL | 临时移走空的 `/etc/hccl_rootinfo.json`，测完恢复 | 同左 |

## 1. TP=4：通过

- `/health` 75 s 就绪；每卡权重 16.52 GiB、KV 54.58 GiB；
- 图捕获 6 张（PIECEWISE 3 + FULL 3）；
- 100-token greedy 请求完整返回：
  `' Paris, a city renowned for its rich history, culture, and iconic landmarks. ...'`；
- Worker 指标：

```json

 "decode_calls":99,"decode_graph_hits":99,"decode_fallbacks":0,
 "attention_backend":"vllm_ascend.attention.attention_v1.AscendAttentionBackend",
 "errors":0}
```

## 2. TP=8：未验证（首个请求挂住）

- `/health` 90 s 就绪；每卡权重 8.36 GiB、KV 62.75 GiB；
- 图捕获 6 张（PIECEWISE 3 + FULL 3）；
- **第一个请求没有完成**：EngineCore 显示 `Running: 1 reqs`，generation throughput 从
  1.8 tok/s 掉到 0；60 s 后日志出现
  `No available shared memory broadcast block found in 60 seconds`，响应为空；
- metrics 里 `captured_graphs=6`，但 `decode_calls=0`——说明卡在请求执行前/图回放阶段，
  不是 TileInfer 的计数问题。

判定：**TP=8 未验证**。这是厂商/HCCL/图路径的挂起，不是本轮代码改动引入；要查需要
厂商侧排查（或换更小的模型/参数隔离）。不要写成"TP=8 支持"。
