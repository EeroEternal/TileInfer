# 性能测试组件 · 开发目标（v1）

> 一句话定位：**一次运行 → 一份能直接指出瓶颈的报告**；能回答"这一步的时间花在哪"，
> 且**异常值必须被点名，不能被平均值掩盖**。
> 现状：入口骨架已在 102（`scripts/ti_trace.py` + `ti_trace.json`），预设/配置/级别/报告目录/设备门已验证；
> 待补的是"真插桩 + 异常检测 + 单次前向全量报告"。

---

## 1. 必须有的功能（6 条）

| # | 功能 | 具体要求 |
|---|---|---|
| F1 | **统一入口** | 只有 `scripts/ti_trace.py`（`run / report / presets / config / level`）+ 一份 `scripts/ti_trace.json` + 一个输出目录 `trace_out/`。原有 `perop*.sh`、`prefill_timing.sh`、`stepshare_ab.sh`、`tpot_leaf.sh` 收成**预设**，不再单独使用 |
| F2 | **三层时间账** | 阶段（MoE/GDN/注意力/稠密/采样）→ 层（0–39）→ 算子；每次调用记 **三列**：`host`（提交耗时）、`dev`（设备执行）、`wait`（排队），并记相邻事件的 `gap`（空转） |
| F3 | **单次前向全量报告** | 定向采样某一步（`TILEINFER_TRACE_FORWARD=n`），逐层逐算子出时间线；层默认折叠成一行，只展开有异常的层；完整明细进 CSV 与 trace |
| F4 | **跨步统计** | 只在**可比组**内聚合（phase × stage × op × shape × provider × 是否首次调用）；用中位数/分位数，不用均值代表整体 |
| F5 | **异常检测并置顶** | R1 首次实例 / R2 稳健离群（median+MAD）/ R3 双峰（p90÷p50>3）/ R4 空转异常 / R5 计数异常 / R6 绝对超限；报告的**第一章**是异常摘要 |
| F6 | **固定产物** | `meta.json`、`plan.json`、`summary.md`、`forward_<n>.md`、`stages.csv`、`layers.csv`、`ops.csv`、`anomalies.csv`、`trace.json`（Chrome Trace）+ `raw/` 日志；维护 `trace_out/latest` |

## 2. 硬约束（5 条）

| # | 约束 |
|---|---|
| C1 | **不许用均值掩盖异常**：任何聚合表必须带 `n / mean / p50 / p90 / max / 异常数`；有异常的行必须进异常摘要并标注 |
| C2 | **观测不得改变被测**：关闭档 vs 标准档的端到端配对比值 ≥0.98 |
| C3 | **账目要对上**：`compute + gap + 观测 + 未归因 = wall`，误差 ≤5%；对不上的部分必须单列"未归因"，不许揉进别处 |
| C4 | **捕获安全**：图捕获进行中自动降为 host-only，不抛异常，`meta.json` 标注降级 |
| C5 | **零侵入**：默认关闭；工具本身只依赖标准库（不 import vllm/torch），不改变服务行为；采样上限与开销上限硬编码在工具内 |
| C6 | **必须标注"不可引用"的情形**：首次调用、样本数不足（<16 次）、短序列（输出 <64 token）的 TPOT、跨时间窗的绝对值——报告里要显式打标，不能让人误当结论 |

## 3. 检测级别（一处定义，三处可改）

| 档 | 内容 | 开销 | 用途 |
|---|---|---|---|
| L0 | 关闭 | 0 | **正式性能验收必须用这档** |
| L1 | 阶段级（host 时钟） | <1% | 日常看阶段占比 |
| L2 | 算子级（host+device） | 2–5% | 默认，找瓶颈 |
| L3 | 算子级 + 单次前向全量 | 单步 10–15% | 出"一次前向全量报告" |

配置位置：`scripts/ti_trace.json` 的 `level`（项目默认）→ `ti_trace.py level L2` 写回 → `--level` 临时覆盖；
四档的 env 定义只在 `ti_trace.py` 的 `DEFAULTS["levels"]` 一处。

---

## 4. 验收（5 条，全部可测）

| # | 判据 |
|---|---|
| T1 | 账目闭合：`compute + gap + 观测 + 未归因 = wall`，误差 ≤5%，连续 3 次稳定 |
| T2 | 观测不改变被测：L0 vs L2 端到端配对比值 ≥0.98（4 对） |
| T3 | **异常不被平均掩盖**（关键）：在某层注入固定 20 ms 延迟后——① 异常摘要点名该层该算子；② 其余行中位数变化 <2%；③ 该行仍保留 `max` 与 `异常数` 两列 |
| T4 | 不丢事件：单次前向报告里的事件条数 = 事件流实际条数 |
| T5 | 可对比：两份 `ops.csv` 能直接 diff 出每个算子的前后变化 |

## 5. 本期不做

- 推理期在线测速/自调优（测速需要同步，会破坏图捕获且扭曲被测）
- 自动判定"该换哪个算子"（只给数据，决策属于算子取舍模块）
- 可视化 UI / 跨机聚合（只输出 Chrome Trace，交给 Perfetto 看）
- 替换现有 `ab_report.py` 的双臂对比（两者分工：本工具看**单臂内部**，双臂对比仍走后者的配对协议）
