# Qwen3.6 C2：TP=1 vs TP=2（2026-11-17）

> 问题：多卡场景下，C2 还能不能成立？做法是同一请求在 TP=1 与 TP=2 下各跑一次
> （`temperature=0`、`logprobs=5`），比较 token 与 logprobs。
>
> 结论：**严格 C2（top-5 logprobs 四位小数一致）不通过。** 两个配置在第 7 个生成 token
> 分叉；首 token logprob 差 0.0193，top-5 最大差 0.1237。TP=2 自身两次运行完全一致，
> 所以差异来自 TP 配置，不是随机噪声。

## 0. 配置

| 项 | TP=1 | TP=2 |
|---|---|---|
| 卡 | 物理 2 | 物理 2、3 |
| 端口 | 8138 | 8139 |
| plan | `plan-tp1.json`（`parallel=single`） | `plan.json`（`parallel=tp`） |
| 其他 | `max-model-len 4096`、`max-num-seqs 1`、`gpu-memory-utilization 0.9`、`--skip-mm-profiling` | 同左 + `--tensor-parallel-size 2` |
| 环境 | CANN 9.3.0 + triton-ascend 3.2.2 + 本仓库代码 | 同左 |
| HCCL | 不需要多 rank | 需临时移走 `/etc/hccl_rootinfo.json`（测完已恢复） |

请求：`{"prompt": "The capital of France is", "max_tokens": 16, "temperature": 0, "logprobs": 5}`。

## 1. 结果

| 项 | 值 |
|---|---|
| 文本一致 | ❌ |
| token 一致 | ❌ |
| 首个分叉位置 | 第 7 个生成 token（0 起） |
| TP=1 分叉 token | `" iconic"` |
| TP=2 分叉 token | `" rich"` |
| 首 token logprob | TP1 `-0.609665` / TP2 `-0.628935`，差 **0.01927** |
| 公共前缀上 token_logprob 最大差 | **0.06333** |
| 首 token 共享 top-5 最大差 | **0.10573** |
| 全部位置 top-5 最大差 | **0.12371** |
| TP=2 同输入复跑 | ✅ 文本/token/logprob 完全一致（diff 0） |

TP=1 文本：

```text
 Paris, a city renowned for its iconic landmarks such as the Eiffel Tower,
```

TP=2 文本：

```text
 Paris, a city renowned for its rich history, culture, and iconic landmarks.
```

## 2. 判定

- 按 [`acceptance.md`](../acceptance.md) §2 的 C2 口径（温度 0、top-5 logprobs 四位小数一致），
  **TP=2 相对 TP=1 不通过**；
- 这不是随机性：TP=2 自身两次完全一致；差异只随 TP 配置变化；
- 最可能来源：bf16 下 TP 的 all-reduce / row-parallel 归约顺序、MoE grouped GEMM 的分块与
  路由并列打破方式。greedy 对微小 logit 差异敏感，第 7 token 后就走上了不同分支。
- **不能把"TP=2 能跑"写成"TP=2 与 TP=1 数值一致"**；也不能用"文本看起来都通顺"代替 C2。

## 3. 另一个发现：manifest 的冻结样例在本机不成立

`manifests/qwen3_6.py` 的 benchmark 记的是：

```text
first_token = "Here",  top5[0] = ["Here", -0.030266], ...
```

本机两个配置的首 token 都是 `" Paris"`（TP1 `-0.6097` / TP2 `-0.6289`）。说明这个冻结样例
要么是针对 102 盒子/另一条模板臂采的，要么已经过期。它现在**不能**作为本机 C2 的 oracle；
需要更新或明确它适用的臂。

## 5. 下一步选项

1. **给 TP 定义容差**：把"跨 TP 的 C2"写成显式口径（例如 top-5 差 ≤ x 且固定评估集通过），
   并证明该容差下任务质量不变；不能默默放宽逐位门。
2. **定位数值源**：逐层比较 TP1/TP2 的 logits，按能力（attention / GDN / MoE / all-reduce）
   归因；先怀疑 MoE grouped GEMM 与归约顺序。
3. **控制模型口径**：C2 仍按"同配置"判（TP1 vs TP1）；TP 只声明"可运行、非数值等价"。
4. 更新 manifest 的冻结样例，或标注它只适用于哪台机器/哪个臂。
