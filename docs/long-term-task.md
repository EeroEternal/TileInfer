# 长期任务：TileInfer v3 落地，并在 Qwen3.6 上端到端跑通

> 这份文档是**任务书**：给它一个会话（或一个人）就能开工，不需要额外上下文。
> 与之配套的是 [`architecture.md`](architecture.md)（目标形态）、[`migration-m0.md`](migration-m0.md)（怎么搬）、
> [`acceptance.md`](acceptance.md)（怎么算做到）、[`status.md`](status.md)（现在在哪）。

## 0. 目标（可直接作为会话 goal 的文本）

```
把 TileInfer 从 v2 形态（自带平台层、不装 vllm-ascend）重构为 v3 形态（vllm-ascend 之上的
兼容适配层：平台/worker/显存/KV/图捕获全部归厂商，我们只做"选实现"和"补缺口"），
并在 Qwen3.6-35B-A3B 上跑通端到端：服务能起、输出与 vllm-ascend 基线逐位一致、
图捕获回退为 0、TPOT 与首字 ≤1.10× 基线且吞吐 ≥0.95×。

约束：不改上游源码；不注册平台插件；不在请求路径上编译；接入点总数不超过 8 个。
按 docs/migration-m0.md 的六步推进，每一步都要过它定义的门。
```

## 1. 完成定义（DoD）

四条**分别判定、分别留证**，缺一条都不算完成。

| # | 判定 | 门槛 | 证据形式 |
|---|---|---|---|
| **C1 能跑** | 端到端起服务，固定请求返回完整输出 | 无异常、无截断 | 服务日志 + 完整输出 |
| **C2 跑对** | 与 vllm-ascend 基线逐位一致 | 温度 0，top-5 logprobs 四位小数一致 | 两个后端同一请求的输出对比 |
| **C3 能上图** | 图捕获真的发生 | 捕获次数 > 0 且**回退次数 = 0** | 捕获/回退计数 |
| **C4 跑得快** | 相对基线在门槛内 | TPOT ≤1.10×、首字 ≤1.10×、吞吐 ≥0.95× | 同机同参 A/B 报告 |

附加条件：

- `tileinfer doctor` 四道门全绿；
- Qwen3.6 的声明文件里有上面四条证据的编号；
- 稳态回退计数为 0（不为 0 视为缺陷，不是"正常降级"）。

> **口径注**：上面 C2/C4 里的"基线"指 **vllm-ascend 能正确部署的同一模型**。这四条是
> Qwen3.6（厂商已覆盖）的验收口径，用来说明"我们这层没有变慢、没有跑偏"。
> 将来补厂商缺口时基线可能不存在——那时 C2 改为"与参考实现一致 + 复跑一致"，
> C4 改为绝对口径，见 [`acceptance.md`](acceptance.md) §2.1。
> **不要因为"没有基线"就跳过 C2/C4**，也不要为了凑一个比值去跨场景比。
> 同理，厂商已经能正确部署的能力不产生缺口，也就不该出现"我们的实现"（[`extending.md`](extending.md) §3.0）。

## 3. 工作顺序

顺序不能换：**先跑对，再让启动可预测，再让图捕获生效，最后谈性能。**

### 3.1 开工前必须先定稿的四份接口产物

M0 不依赖它们；**M1 依赖**。没有它们，写代码的人只能现场发明字段，后续必然返工。

| 产物 | 为什么必须在写代码前定 |
|---|---|
| **计划文件 schema** | 决策的输出、构建的输入、接入层的读入都靠它。字段一改，三层同时动 |
| **模型声明 schema** | 现在只有六条"概念要求"，没有字段级定义；写第一个声明时必然现场发明 |
| **8 个契约的接口签名** | 提供者要照着它写；没有签名，"实现什么"只能靠猜 |
| **缺口报告格式** | 它是"新模型上线成本可预测"的唯一凭据，格式不定就没法自动列出 |

| 阶段 | 目标 | 进入条件 | 退出条件 |
|---|---|---|---|
| **M0 迁移** | 把 v2 代码搬进 v3 分层，**行为一位不变** | 有基线（S0） | [`migration-m0.md`](migration-m0.md) §5 全部满足 |
| **M1 Qwen3.6 在 v3 上跑通** | 声明 → 决策 → 注入 → 服务出正确结果 | M0 完成 **且 §3.1 四份产物定稿** | C1 + C2 |
| **M2 启动可预测** | 预编译内核集，请求期零编译 | M1 完成 | 冷启动不编译；部署耗时 = 可测量常数 |
| **M3 图捕获** | 稳态零策略、回退为零 | M2 完成 | C3 |
| **M4 性能过门** | 与基线 A/B | M3 完成 | C4 |
| **M5 扩展性验证** | 第二个模型走完整流程，**优先选厂商部署不了的**（这样缺口清单非空，才验证得到补缺口） | M4 完成 | 缺口报告与实际工作量一致；接入点 ≤8 |

**M5 之前不要做**：通用 provider 框架、第二个硬件、TP/EP、量化。

## 4. 硬约束（违反即回退该改动）

1. **不改上游源码。** 只允许：安装期注册入口、启动期换表、包装方法。
2. **不注册平台插件。** 一个进程只允许一个平台；我们去注册只会撞车，且收益为零。
3. **不重写平台层。** 设备 / worker / 显存 / KV 池 / 图捕获归厂商——v2 已经用 2.53× 的代价证明过一次。
4. **接入点 ≤8（现为 6）。** 超了必须写例外说明并重新设计。
5. **稳态零策略。** 每步没有分支、没有查表、没有主机侧同步。
6. **禁止请求期编译。** 编译只在构建期；运行期只允许命中缓存。
7. **禁止静默回退。** 回退要计数、进日志、能被测试断言为"不允许发生"。
8. **入口函数绝不向外抛异常。** 上游只 catch 模块导入，不 catch 函数执行；抛出去就是整个进程起不来。
9. **单一真相。** 每个模型一份声明，每个决策一个产物；文档提到的目录必须真实存在。

## 5. 第一天要做的三件事

1. **冻基线**：逐文件测试结果 + `ti_trace run --preset smoke` 数字 + `HEAD` 提交，写进 `docs/notes/m0-baseline.md`。
   没有基线，"行为一位不变"这个门就是空话。
2. **改守卫**：`tests/test_no_vllm_ascend.py` 现在是"全局禁止 import vllm_ascend"（v2 的约束）。
   v3 要求 `bridge/` 能 import 它。改成**分层禁令**：内核 / 契约 / 决策 / 预编译层不许，只有接入层可以。
   不改这个，第一次写接入点就被 CI 判红。
3. **立骨架**：建空目录 + `__init__` + import 规则检查。**这一步不搬任何文件**。

## 6. 已知陷阱（每一条都实际发生过）

| 陷阱 | 表现 | 应对 |
|---|---|---|
| 平台槽位撞车 | 两个插件都声称提供平台 → 进程直接起不来 | 只允许厂商注册；返回厂商的类也不能免掉冲突 |
| 注意力后端选择有缓存 | 包装了却没生效 | 必须在任何前向之前完成 |
| 同名实现是断言不是覆盖 | 注册时直接抛错 | 收敛成**一个**接管函数，并记"接管自谁" |
| 子类覆盖吃掉包装 | 包了基类，但实际跑的是子类 | 包实际类，或在探测阶段发现 |
| 编译占住解释器 | 引擎不响应，A/B 跑到一半卡死 | 编译只在构建期 |
| CPU 套件本来就是红的 | 整套 80 项失败，逐文件是绿的 | 门只能用"逐文件 + 与基线比" |
| 表写对了但没生效 | 进程里看不到我们的实现 | 装完立刻探测 + 运行期打点 |
| 文档与代码脱节 | 按文档建目录，结果代码里没有 | 文档写不存在的目录时必须标"计划" |

## 7. 每轮会话的协议

**开始**：
1. `git log -1` + `git status`（确认起点干净）；
2. 读 [`status.md`](status.md) §0–§2（现状与断点）；
3. 找到当前游标（M0 的 S 步，或 M1–M5 的哪一项），只推进一项。

**结束**：
1. 更新 [`status.md`](status.md)：建成了什么（附证据）、哪里断了；
2. 证据落盘（命令、时间戳、数字），没有证据的能力不进状态表的"已建成"列；
3. 一个提交一个主题；提交信息写"为什么"，不写"改了什么"。

**中断恢复**：游标永远在文档里，不在会话记忆里。新会话只读文档就能接上。

## 8. 停止条件（触发就把结论写进 status，不要硬推）

| 触发 | 动作 |
|---|---|
| 上游每个小版本要改 ≥3 个接入点 | 收缩到"模型实现 + 2–3 个高价值算子"，砍掉通用层 |
| 某类契约只有一个提供者且从未被替换 | 判定为抽象税，合并回模型层 |
| 稳态回退压不到 0 | 停止加模型，先修回退根因 |
| 某模型适配超过"照上游办法硬改"的 3 倍 | 放弃通用路径，退化为专用分支并记录 |
| 两次尝试后仍无法定位失败层 | 停下来补观测，不要继续改代码 |
